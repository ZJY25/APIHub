# NewAPI 改造企业私有 APIHub（TokenHub）任务清单

> 适用场景：企业内网私有化部署，仅内部业务/研发使用，不对外售卖服务
> 基线：原版 NewAPI（Go 网关 + React 控制台，支持 SQLite / MySQL / PostgreSQL，日志库支持 ClickHouse）
> 目标规模：约 2000 人团队，峰值 500~800 QPS
>
> 优先级：P0=投产必做；P1=审计计量与架构必备；P2=稳定运维；P3=迭代增强
> 类型标记：[已有] 代码已内置，只需验收或调参；[改造] 在现有实现上修改；[新增] 需要新开发

## 零、目标与容量基线

- [P0] [ ] 明确容量口径：区分「峰值 QPS」「平均 QPS」「峰值并发流」「平均请求时长」，不要只写一个 QPS 数字。
     参考换算：800 QPS × 平均 20 秒 ≈ 1.6 万并发流；按 2000 人日常使用，按 2000~5000 并发做资源预算。
- [P0] [ ] 固定架构基线：PostgreSQL 15+ 主库 + 共享 Redis + 独立 ClickHouse 日志库 + 3 个以上无状态实例。
- [P0] [ ] 明确可用性目标：单实例故障不影响服务、滚动升级不中断、RPO/RTO 指标。
- [P1] [ ] 明确「不保存 Prompt/返回原文」的数据合规红线（当前系统默认也不保存，见附录 A）。

## 一、基础部署 & 存储改造

- [P0] [改造] 数据库固定为 PostgreSQL 15+（当前代码已支持三库，但 800 QPS 场景不保留 SQLite/MySQL 选项）；关闭公网访问，仅内网网段可连。
- [P0] [改造] 日志库物理分离：`LOG_SQL_DSN` 指向独立 ClickHouse（当前已支持），业务库只保留短期统计；配置 `LOG_SQL_CLICKHOUSE_TTL_DAYS` 保留周期。
- [P0] [新增] 共享 Redis：多实例共享限流、令牌/用户/渠道缓存；`REDIS_POOL_SIZE` 从默认 10 调到 50~100。
- [P0] [改造] 编排升级：单机 Docker → Docker Compose / K8s，至少 3 实例；设置共享 `SESSION_SECRET`、`CRYPTO_SECRET`，主节点 `NODE_TYPE` 配置正确。
- [P0] [已有] 持久化与备份：数据卷持久化、数据库异地定时备份、恢复演练。
- [P0] [已有] 网络拓扑：部署在内网子网，控制台经企业 Nginx/Ingress 反向代理，不直接暴露公网。
- [P0] [已有] 镜像版本固定：不使用 `latest`，打包进私有镜像仓库。
- [P1] [改造] PostgreSQL 主从/只读副本：按压测结果决定是否需要，不作为 800 QPS 的前置条件。
- [P1] [已有] 出口网络：经企业代理/安全网关访问上游，配置厂商出口 IP 白名单。
- [P1] [新增] 全链路容量验收：见「十一、上线前验证」。

## 二、身份认证 & 权限体系

- [P0] [已有] 企业 SSO：使用通用 OIDC（仓库已内置 `oauth/oidc.go`、`oauth/generic.go`），关闭本地注册与个人社交登录。
- [P0] [改造] 账号安全策略：会话超时、刷新轮换、Cookie 安全已有；密码复杂度、登录失败锁定、后台二次验证需确认并补齐。
- [P0] [新增] 多租户数据模型：Organization / Team / Project + 成员关系表，作为权限、配额、账单的统一维度。
- [P1] [改造] 角色体系：现有 Casbin 为「资源 + 动作」的平台级 RBAC，仅 `root`/`admin` 两个内置角色（`service/authz/`）；在其上扩展「组织管理员 / 项目管理员 / 开发者 / 审计只读」角色，主体使用 `project:<id>`，不要引入第二套鉴权。
- [P1] [新增] 资源级隔离：A 项目不可查看 B 项目的令牌、调用记录、用量与账单。
- [P1] [新增] 渠道权限隔离：渠道绑定到项目/团队，仅授权项目可选该渠道。
- [P1] [已有] 模型白名单：`Token.ModelLimits` 已内置；只需补批量维护与界面体验。
- [P1] [已有] 后台操作审计：`AuditLog` 已内置（login/security/operation/access_token 四类，含操作人、IP、UA、路由、状态、request_id）；补 Token 生命周期与额度变更的强制覆盖、导出和保留策略。
- [P1] [新增] OIDC 组声明映射角色（IdP group → 项目/角色）；SCIM 自动开户按企业 IdP 能力决定是否实施。

## 三、日志 & 审计改造

- [P1] [改造] 补齐日志字段：`status_code`、`error_code`、`project_id`、`department_id`、`service_name`；现有 `request_id`、`upstream_request_id`、耗时、渠道、分组、IP、token 数已具备（`model/log.go`）。
- [P1] [已有] 不保存 Prompt/返回原文：当前只落计费说明 JSON；如合规需要审计原文，单独设计脱敏与最小化留痕，不直接打开原文存储。
- [P1] [改造] 结构化输出：沿用日志 `content`/`other` 的 JSON 结构，新增字段后同步索引与前端展示。
- [P0] [改造] 生命周期管理：ClickHouse 归档 + TTL；业务库仅保留近 7 天统计，超期清理。
- [P1] [已有] 日志自动清理：按合规保留周期配置（`LOG_SQL_CLICKHOUSE_TTL_DAYS`）。
- [P1] [改造] 日志检索：支持按项目、部门、时间、模型、错误码检索；补审计报表导出。
- [P2] [新增] 异常调用标记：高频请求、超大上下文、大额消耗单独标记与告警。

## 四、计量、计费 & 配额体系

- [P1] [已有] 计价能力：按模型价格/倍率、输入/输出分别计价（`setting/ratio_setting`、`service/text_quota.go`、`pkg/billingexpr`）；按渠道独立定价按需补充。
- [P1] [新增] 虚拟 Key 预算：Token 增加「预算金额 + 日/月周期 + 自动重置」，替代单一的总额度。
- [P1] [新增] Key 级限流：per-key RPM / TPM / 并发上限，落 Redis 滑动窗口；现有限流是「用户 + 模型」维度（`middleware/model-rate-limit.go`）。
- [P1] [新增] 配额维度扩展：项目/部门总额度、日额度、小时额度。
- [P1] [已有] 配额预警：现有额度提醒开关可复用；补项目/部门阈值通知。
- [P2] [新增] 额度冻结/解冻 HTTP 接口，支撑业务自助申请。
- [P1] [新增] 多维度用量报表：按项目、部门、模型、时间统计用量与成本，支持导出。
- [P2] [新增] 对外账单接口，供财务成本平台拉取计量数据。

## 五、模型网关核心能力（路由、协议适配）

- [P0] [已有] 渠道路由：优先级/权重选择、失败重试、跨分组重试已内置；本阶段做超时、重试次数、渠道状态验收与调参。
- [P2] [改造] 高级路由：现有分组机制可承载「项目 → 渠道」标签路由，配合第二章的渠道授权落地。
- [P2] [新增] 熔断降级：上游持续报错自动熔断，防止雪崩；优先在上游错误码维度实现。
- [P2] [改造] 协议补丁：国产模型、Claude 扩展参数、多模态图片、thinking 参数兼容问题按实际接入清单逐项修。
- [P2] [改造] SSE 流式稳定性：以压测中的断流、乱码、超时场景为准做加固（`STREAMING_TIMEOUT`、`RELAY_RESPONSE_HEADER_TIMEOUT`）。
- [P2] [新增] 请求预处理插件：Prompt 敏感信息脱敏、上下文长度前置校验、内容安全校验。
- [P1] [改造] 限流体系：保留现有全局 + 用户 + 模型限流，新增 per-key 限流与全局并发上限，保护网关。

## 六、运维 & 监控告警

- [P1] [新增] Prometheus `/metrics`：请求量、成功率、失败率、P50/P90/P99 耗时、Token 消耗、渠道错误率；现有 `perf-metrics` 只有 JSON 接口，不是 Prometheus 格式。
- [P1] [新增] Grafana 看板与容量水位：QPS、并发流、DB 连接数、Redis 命中率/池占用、ClickHouse 写入量。
- [P1] [新增] 告警规则对接企业告警平台/钉钉/企业微信：宕机、错误率突增、上游大面积报错、额度异常、超长耗时请求。
- [P2] [已有] 健康检查：`/api/status`、`/api/uptime/status` 可直接做 K8s 探针。
- [P2] [已有] 上游渠道定时可用性探测与状态标记：已内置定时任务，验收即可。
- [P2] [新增] 运维工具：一键禁用/重置 Token，批量导入导出渠道与用户配置。
- [P2] [新增] 灰度发布：K8s 滚动更新 + 健康探针 + 优雅停机（`SHUTDOWN_TIMEOUT_SECONDS`）。

## 附录 C：容量相关关键参数

| 参数 | 默认值 | 建议值 | 说明 |
| --- | --- | --- | --- |
| `REDIS_POOL_SIZE` | 10 | 50~100 | 800 QPS 下默认值会打满连接池 |
| `SQL_MAX_OPEN_CONNS` | 1000 | 50~100 / 节点 | 配合 PG max_connections 与实例数计算 |
| `SQL_MAX_IDLE_CONNS` | 100 | 20~50 / 节点 | 避免空闲连接占满数据库 |
| `BATCH_UPDATE_ENABLED` | false | true | 合并额度/用量写入 |
| `BATCH_UPDATE_INTERVAL` | 5 | 1~5 | 越小实时性越好、写压力越大 |
| `MEMORY_CACHE_ENABLED` | false | true | 渠道选择走内存缓存 |
| `SYNC_FREQUENCY` | 60 | 30~60 | 缓存与配置同步周期 |
| `LOG_SQL_DSN` | 空 | ClickHouse | 日志与业务库分离 |
| `LOG_SQL_CLICKHOUSE_TTL_DAYS` | 0（不删） | 按合规设置 | 日志保留周期 |
| `SHUTDOWN_TIMEOUT_SECONDS` | 120 | 120 | 滚动升级时等待流式请求结束 |
